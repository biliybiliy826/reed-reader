# 微信读书接入计划 · 2026-11-17

## 目标
在苇读 Linux 桌面应用中阅读微信读书官方网页版，支持用户自行扫码登录、官方书架及阅读页、独立小窗、全局显隐、透明度、页面缩放与会话保留。

## 决策与边界
- 使用 Qt WebEngine 加载官方 HTTPS 网页；书籍授权、购买与阅读进度交由官网处理。
- 不将网页正文转换/导出为本地电子书，不读取或导入其他浏览器的 Cookie。
- 独立浏览器 profile；只在用户点击微信读书入口/执行 --weread 时创建并联网。
- 网页阅读窗口拥有独立位置/尺寸；全局命令针对最后激活的阅读窗口，隐藏全部涵盖本地和网页窗口。
- 保留系统浏览器打开入口，用于官方服务拒绝嵌入式内核或需要外部授权时。
- 原 AGENTS.md 的 Legado-only 网络范围被本次用户明确要求扩展到微信读书官方网页。

## 基线
- 工作树干净，版本 0.1.0，提交 4bc02e1。
- 修改前 39 项测试通过；ruff 通过。
- 图索引不可用：项目不在图服务允许根目录内，采用本地源码读取，没有修改服务全局允许列表。

## 验证要求
自动测试使用本地 HTML/临时 profile，不能访问用户账号。官网检查使用未登录会话，只记录加载成功、页面标题和控件可用性。真实登录后书架、受权限限制的小说以及跨设备同步需要用户扫码后实测，不提前声称完成。

## 回滚
源码可回到 4bc02e1；本地 SQLite schema 不变。新增 profile 与原有本地图书分开；回退代码不删除用户登录数据或书籍。安装依赖锁文件纳入版本控制。

## 用户审阅纠正 · 2026-11-17

用户已经在微信读书登录并打开小说，提供截图指出“没有 Fish 的效果”。截图说明：整窗透明会同时淡化字和背景；应用标题/地址栏、官网导航、侧栏仍占大量面积，不符合几行文字浮在桌面的核心目标。

接入目标据此补充为两种明确模式：完整官网用于登录/选书，摸鱼模式用于阅读，隐藏原生及网页装饰、窄条窗口、透明背景与可读文字。允许在当前已授权显示的官方阅读页应用可撤销的呈现样式，不读取隐藏正文、提取 Cookie 或绕过权限。此前“不注入任何样式”的设计选择不再适用；保留不导出正文的边界。

必须验证真实呈现结构（DOM/canvas）、进入/退出可逆、官网登录弹窗不被遮挡、模式切换保持当前会话与位置，并通过实际截图检查文字和桌面背景的视觉结果。

## 完成与验证

- 版本 0.2.0，新增 Qt WebEngine 官方网页窗口、独立 profile、会话清除、UI/CLI/托盘入口和最后激活窗口快捷键路由。
- 根据用户截图纠正了“半透明浏览器套壳”的设计：透明阅读条 840×130、无框、强制置顶、隐藏任务栏条目、独立文字/背景 alpha、悬停操作和可撤销网页装饰样式。
- `QT_QPA_PLATFORM=offscreen uv run pytest -q`：75 passed；`uv run ruff check .`：通过。
- 原生官网未登录加载验证通过；用户完成登录并提供阅读截图，随后在同一个应用 profile 上验证真实正文 Canvas 的透明性、宽度重排、装饰去除及屏幕叠加效果。未导出 Cookie 或正文。
- 独立原创文本视觉回归验证透明像素和非空字形，见 `weread-fish-visual.json` 与 `screenshots/weread-fish-demo.png`。
- Qt 6.12 分包后只装 Addons 没有 WebEngine，已改为明确依赖 PySide6-WebEngine 并锁定解析结果。
- 发现并修复 QUrl 空 user-info/query/fragment 残留、WebEngine 页面/profile 释放顺序、网页残留 navBarOffset 与 chapterTitle 顶部空白、离开阅读页后恢复完整窗口等问题。
- 官方手机进度同步未做双设备核对；Wayland 未实测。官网版本变化可能导致样式选择器需要更新。

## 审阅结论

初版只做到了网页登录与整窗透明，未满足原始 Fish 隐蔽阅读目标；本次补齐了透明文字条，并以真实桌面画面和像素回归验证取代仅检查窗口尺寸。当前测试不代表对付费权限、跨设备同步或所有官网布局的验证。

## 一键隐藏补充 · 2026-11-17

- [x] F8、Ctrl+Alt+H 和鼠标中键均执行隐藏全部；Alt+V/托盘恢复，不把隐藏键实现成显隐切换。
- [x] X11 RECORD 仅观察鼠标按下事件，不监听键盘内容、不阻断其他客户端中键；可关闭全局中键。Wayland 仅窗口内中键，键盘全局需桌面绑定。
- [x] 单个全局键冲突不再导致其他键全部失效，冲突键提供应用内回退。
- [x] 挂起的网页呈现回调不重新显示已隐藏窗口；设置弹窗一并关闭。
- [x] 原生 X11 输入验证通过，记录于 `panic-shortcuts-verification.json`；正常网页与透明条内中键、快捷键隐藏和恢复纳入测试。
- 验证发现 Qt 6.12 全应用 Python 事件过滤器在 WebEngine 重建原生窗口时触发 Shiboken 包装已销毁 QObject 的崩溃；改为仅对活跃 QWidget 安装过滤器，并覆盖动态子控件。
- 关闭应用时停止阅读/书架延迟定时器，防止测试或嵌入式生命周期中访问已关闭数据库。

最终运行验证：正常 CLI 实例已替换诊断实例，保留原登录会话；840×130 透明阅读条上实测 F8 / Ctrl+Alt+H 连续隐藏、全局中键隐藏和 Alt+V 恢复均通过。原生原创文本视觉脚本退出码 0；临时浏览器目录的延迟写入清理竞态已加入有界重试。
